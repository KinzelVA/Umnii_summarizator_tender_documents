# Логика решения: умный суммаризатор тендерной документации

## 1. Цель

Сервис принимает PDF-файл с тендерной документацией и возвращает структурированную краткую выжимку:

- сумму контракта;
- сроки выполнения;
- ключевые требования к исполнителю;
- штрафы и неустойки.

API реализуется на FastAPI. Для анализа извлеченного текста используется LLM.

## 2. Общая архитектура

Поток обработки документа:

1. Клиент отправляет PDF-файл через HTTP API.
2. FastAPI проверяет тип и корректность входного файла.
3. Сервис извлекает текст из PDF.
4. Текст очищается и подготавливается для передачи в LLM.
5. При необходимости большой документ разбивается на части.
6. LLM анализирует содержимое документа.
7. Ответ модели преобразуется в заранее определенную структуру.
8. FastAPI валидирует результат через Pydantic и возвращает JSON клиенту.

Слои приложения разделены по ответственности:

- API — HTTP endpoints и валидация запросов;
- PDF service — извлечение текста из PDF;
- LLM service — взаимодействие с языковой моделью;
- schemas — модели входных и выходных данных;
- core — конфигурация приложения и общие настройки.

## 3. Алгоритм обработки PDF

1. Проверить, что загруженный файл имеет формат PDF.
2. Проверить ограничение размера файла.
3. Попытаться извлечь текстовый слой документа.
4. Если текст отсутствует, вернуть понятную ошибку о том, что OCR в текущей версии не поддерживается.
5. Удалить лишние пробелы и технические переносы строк.
6. Передать подготовленный текст в слой анализа.

Первая версия сервиса ориентирована на PDF-файлы, содержащие текстовый слой.

OCR для отсканированных документов рассматривается как возможное дальнейшее развитие проекта.

## 4. Работа с большими документами

Тендерная документация может содержать десятки или сотни страниц и превышать контекстное окно LLM.

Поэтому для больших документов используется разбиение текста на части.

Алгоритм:

1. Разбить документ на логические текстовые блоки.
2. Проанализировать каждый блок отдельно.
3. Извлечь потенциально значимые данные.
4. Объединить результаты.
5. Выполнить финальную нормализацию результата.

Это позволяет избежать передачи всего документа одним запросом и уменьшает риск превышения лимитов модели.

## 5. Структурированный ответ LLM

Модель должна возвращать данные в заранее определенной структуре.

Пример:

```json
{
  "contract_amount": "15 000 000 RUB",
  "execution_deadlines": "с 01.09.2026 по 31.12.2026",
  "contractor_requirements": [
    "наличие лицензии",
    "опыт выполнения аналогичных контрактов"
  ],
  "penalties": [
    "0.1% от стоимости обязательства за каждый день просрочки"
  ]
}
